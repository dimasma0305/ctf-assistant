# Isolated Codex worker

The Discord bot lets its chat model decide when to submit a CTF solve or multi-step investigation over `/run/hackerika-codex/control.sock`. A trusted host controller owns Docker and the ChatGPT sign-in session. Every job runs in a fresh container with no network, no credentials, no Docker socket, a read-only root, dropped capabilities, and disposable `/workspace` and `/tmp` filesystems. Only a per-job inference/source Unix socket enters the worker. Containers share the host kernel; this is container isolation, not a VM boundary.

Build the pinned worker from the matching standalone Codex release. The controller also checks this image before each job and rebuilds the pinned release if Docker has pruned it:

```sh
bun scripts/codex-runner/build.ts /root/.codex/packages/standalone/releases/0.163.0-x86_64-unknown-linux-musl/bin
```

The build includes two reviewed skills from the pinned [irai bundle](skills/README.md):
`ctf-deep-solve` and `resourceful-solve`. Each job copies them into its disposable
workspace for Codex skill discovery. The worker still has only the tools and
access granted by this runner.

Install `controller.env.example` as `/etc/hackerika-codex-controller.env` with mode `0600`, install the service unit, and enable it. The bot container mounts only `/run/hackerika-codex` read-only through `docker-compose.codex.yml`; it never receives the Docker socket. GPT-6 Sol is the default agent model; Luna remains an explicit option for light jobs. The chat model can request Daybreak Blue for a more demanding job, but the controller accepts that choice only for allowlisted requestors. No keyword in the task silently changes the model.

Creative image requests use the trusted gateway's `/images/generate` endpoint. Configure a valid `OPENAI_IMAGE_API_KEY` in `/etc/hackerika-codex-controller.env` and restart the controller to enable it. The ChatGPT plan token used for text jobs cannot invoke image generation through its subscription-sharing route. The image key stays on the host and is never passed to a worker. The endpoint makes at most one image per job with `gpt-image-2.5-flare` at low quality by default (override with `OPENAI_IMAGE_MODEL`); it returns WebP bytes, which the worker saves under `/workspace/exports` for normal Discord attachment delivery. API image usage is billed separately. Without a valid image key, the worker can still draw a stylized SVG comic or illustration and rasterize it with `rsvg-convert`. It must describe that as a code-drawn image, and verify the exported PNG instead of returning a prompt or claiming image generation succeeded.

The controller allows one active job globally, one outstanding request per channel (a multi-person investigation can use one joint job or atomically enqueue two or three focused jobs), three submissions per user per hour by default and twelve for the Daybreak-allowlisted owner, up to fourteen CTF or thirty-six investigation model calls per job, a ten-minute CTF or fifteen-minute investigation deadline, and an eight-job queue. A CTF job may retry once if a flag was printed only by a failed command. The worker includes a minimal PHP source-build toolchain and has a 1 GiB disposable workspace, 3 GiB memory limit, and two CPUs so source-level reproducers can be compiled and tested in isolation. It caps individual files at 256 MiB to prevent runaway crash logs; AddressSanitizer builds in this container need `-fno-pie -no-pie` to avoid spurious `DEADLYSIGNAL` output. The gateway permits at most two public searches and eight guarded source reads for CTF, or six searches and sixteen reads for investigation, and rejects flags and credentials in search queries. Static slide sites expose their script and slide-module links as source reads. The worker can download up to three discovered public artifacts of at most 8 MiB each through the same DNS-pinned URL guard, then inspect them in its disposable workspace. During a job the worker can request up to six fresh Discord reads through the bot. Public URLs contained in those freshly authorized messages can be read through the guarded source gateway. The bot checks the requestor's and bot's current history access, restricts reads to the job's channel/thread, and returns bounded text, embed metadata, and at most one image's actual bytes per read. When explicitly requested, at most two Luna vision calls per job inspect those bytes; repeated identical images reuse an in-memory observation. The worker cannot access Discord credentials, other channels, or members' DMs. The controller keeps private job metadata for 24 hours and discards raw input artifact bytes as soon as a job reaches a terminal state; live Discord read responses and image observations are not persisted. If the worker exports a requested result, at most two regular files (4 MiB each, 6 MiB combined) are stored privately until the bot replies in the original channel/thread, then deleted; undelivered files expire after 24 hours. A restart marks interrupted work failed rather than spending the plan again.

Codex `exec` does not expose the interactive `/goal` command in this worker. The job now supplies an evidence-checked completion contract and keeps its disposable Codex thread on disk for the job lifetime. If an answer identifies a concrete, untried, in-scope `nextStep`, the worker can resume that same thread for up to two distinct steps within the original model-call and wall-clock limits. A failed continuation keeps the last usable answer. Session files disappear with the container; no thread or credentials are shared across jobs. A verified absence of public self-disclosure is a legitimate stopping point for profile research, not an instruction to keep deanonymizing someone.
